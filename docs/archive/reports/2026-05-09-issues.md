## Implementation Plan: Final Architectural Consolidation

> [!IMPORTANT]
> **Mandatory Architectural Compliance**
> All implementations must strictly adhere to the [ENGINE_GUIDELINES.md](docs/ENGINE_GUIDELINES.md). The next developer (AI or human) must prioritize:
> 1. **Phase-Driven Execution**: No logic should run outside the registered `Phase` loop.
> 2. **Intent-Based Interaction**: Systems must use Intent components for actions, never direct method calls or out-of-band mutations.
> 3. **Single Source of Truth**: Only the authoritative Combat System should resolve damage; only the Gravedigger System should destroy entities.
> 4. **No Direct Mutations**: Always use `world.patchComponent` for state updates.

This plan is for the next developer to finalize the Phase-Driven Intent pattern. Follow these steps exactly to ensure no logic duplication or "ghost" state remains.

### Objective 1: Consolidate Death into the "Dying" Pipeline
**Goal**: Centralize all entity removal logic so that loot, currency, and cleanup always trigger, regardless of how the entity died (Melee, Ranged, DoT, Environmental).

1.  **Modify `src/game/systems/combat.ts`**:
    - Open `handleDeath`. **Delete** `grid.removeEntity(...)` and the entire `lootTable` rolling loop.
    - **Delete** the call to `applyVampireOnKill` (we will move this to a reaction system).
    - The `handleDeath` function should now do ONLY two things:
        1. `eventBus.emit('ENTITY_DIED', { ... })`
        2. `world.addComponent(entityId, Dying, { killerId })`
2.  **Clean up `firmware.ts`, `pack-coordinator.ts`, and `dead-zone.ts`**:
    - Search for all instances of `world.destroyEntity(id)`.
    - **Replace** them with `world.addComponent(id, Dying, { killerId })`.
    - **Rule**: ONLY the `GravediggerSystem` is allowed to call `world.destroyEntity`. No exceptions.

### Objective 2: Unify Loot & Currency into "RewardDropSystem"
**Goal**: Ensure all deaths drop both equipment and currency consistently.

1.  **Rename System**: Rename `src/game/systems/currency-drop.ts` to `reward-drop.ts`. Update the export to `createRewardDropSystem`.
2.  **Migrate Equipment Loot**: Move the `LootTable` rolling logic from the old `combat.ts` into this system's `update` function.
3.  **Process `Dying`**: The system must query for all entities with the `Dying` component during `Phase.CLEANUP`.
4.  **Action**: For every dying entity, roll for Currency (Scrap/Flux/Blueprints) AND its `LootTable` for equipment. Spawn all items at the entity's last known position.

### Objective 3: Standardize Combat via `DamageIntent`
**Goal**: Stop systems from calculating damage themselves. All defense/armor logic must live in one place.

1.  **Add Component**: In `src/shared/components/intents.ts`, add a `DamageIntent` component:
    ```typescript
    export const DamageIntent = defineComponent('damageIntent', z.object({
      targetId: z.number(),
      amount: z.number() // The fixed damage from an ability or effect
    }));
    ```
2.  **Update `CombatSystem`**:
    - In the `update` loop, query for `DamageIntent`.
    - For each intent: `finalDamage = Math.max(1, intent.amount - defenderArmor)`.
    - Apply `finalDamage` to the target's `Health` component.
    - If health reaches 0, call `handleDeath(targetId, attackerId)`.
3.  **Refactor `FirmwareSystem`**:
    - In `activateAbility`, find the code that calculates damage and subtracts health.
    - **Replace** it with: `world.addComponent(entityId, DamageIntent, { targetId, amount: abilityDef.damageAmount })`.

### Objective 4: Implement BLEED Damage Application
**Goal**: Make status effects meaningful.

1.  **Modify `src/game/systems/status-effects.ts`**:
    - In the `tickDown` function, add a check: `if (effect.name === 'BLEED')`.
    - Calculate damage based on `effect.magnitude`.
    - Patch the entity's `Health`.
    - **Crucial**: If the health drops to 0, you MUST add the `Dying` component immediately.

### Objective 5: Fix Legacy Direct Mutations
**Goal**: Stop bypassing the ECS store.

1.  **Modify `src/game/systems/pack-coordinator.ts`**:
    - Find line ~67: `statusEffects.effects.push(...)`.
    - **Replace** with:
      ```typescript
      world.patchComponent(player.id, StatusEffects, {
        effects: [...statusEffects.effects, { name: 'MOVEMENT_SLOW', ... }]
      });
      ```
    - This ensures the change is serialized and synced correctly.
