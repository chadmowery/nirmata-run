## Spacing Scale

All tokens are already defined in `globals.css` as CSS custom properties. Use them exclusively — do not hardcode px values.

| Token | Value | CSS Variable | Usage |
|-------|-------|-------------|-------|
| xs | 4px | var(--space-xs) | Icon gaps, tree item indent markers, badge padding |
| sm | 8px | var(--space-sm) | Sidebar item vertical padding, form field gaps, label-to-input gap |
| md | 16px | var(--space-md) | Panel content padding, form section gaps, editor field padding |
| lg | 24px | var(--space-lg) | Section separators within main panel, editor group spacing |
| xl | 32px | var(--space-xl) | Main layout gap between sidebar and panel |
| 2xl | 48px | var(--space-2xl) | Top/bottom padding of the full-page tool shell |
| 3xl | 64px | not yet in globals.css — use var(--space-2xl) as max | Not needed in this phase |

Exceptions:
- Sidebar width: 280px fixed (not a spacing token — structural layout value).
- Tree item row height: 36px min-height to meet 44px touch-target accessibility guidance; use padding to achieve this since the sidebar is developer-only (36px acceptable for desktop dev tool).
- Validation error strip below a form field: 4px top margin + 12px font-size (var(--font-size-label)).

## Typography

All font sizes are defined in `globals.css`. Use CSS variables — never hardcode.

| Role | Size | CSS Variable | Weight | CSS Variable | Line Height | Usage |
|------|------|-------------|--------|-------------|-------------|-------|
| Display | 48px | var(--font-size-display) | 600 | var(--font-weight-semibold) | 1.0 | var(--line-height-display) — Reserved for page-level titles only (not used in Phase 17) |
| Heading | 24px | var(--font-size-heading) | 600 | var(--font-weight-semibold) | 1.2 | var(--line-height-heading) — Editor panel title (e.g., "ENTITY_TEMPLATE: null-pointer"), section headers |
| Body | 14px | var(--font-size-body) | 400 | var(--font-weight-regular) | 1.5 | var(--line-height-body) — Form field values, sidebar tree item names, description text |
| Label | 12px | var(--font-size-label) | 400 | var(--font-weight-regular) | 1.2 | Form field labels, validation error messages, sidebar section header caps |

Rules:
- All heading and label text: `text-transform: uppercase; letter-spacing: 0.05em` — consistent with established patterns in AnchorOverlay.module.css and styles.module.css.

- No italic text anywhere in this tool.

Source: globals.css direct read, confirmed by AnchorOverlay.module.css and styles.module.css usage patterns.

## Color

All color values are defined in `globals.css` as CSS custom properties. Use variables exclusively.

| Role | Value | CSS Variable | Usage |
|------|-------|-------------|-------|
| Dominant (60%) | #000000 | var(--black) | Full-page background, sidebar background, editor panel background |
| Secondary (30%) | rgba(0, 0, 0, 0.95) | var(--overlay-bg) / rgba(0,0,0,0.85) | Modal/dialog surfaces (delete confirmation), active sidebar item highlight background |
| Accent — Secure (10%) | #00F0FF | var(--vibrant-cyan) | Save button, sidebar section headers, active selection border, field focus ring, category headers in tree |
| Accent — Danger | #FF0055 | var(--vibrant-pink) | Delete button, validation error text, required field indicator asterisk |
| Warning | #FF9500 | var(--safety-orange) | ECS consistency rule warnings (non-blocking), dirty-state indicator dot |
| Text primary | #FFFFFF | var(--white) | Editor panel titles, form field values, sidebar item names |
| Text secondary | rgba(255,255,255,0.5) | — | Form field labels, placeholder text, tree item secondary info (file path) |
| Text dim | rgba(255,255,255,0.3) | — | Empty state body text, disabled field values |
| Border default | rgba(255,255,255,0.1) | — | Panel borders, form field input borders, dividers |
| Border active | rgba(0,240,255,0.3) | — | Sidebar item hover/active border-left, focused input border |

Accent reserved for:
- var(--vibrant-cyan): Save button fill, sidebar section header text, active tree item left-border, focused input border color, "SECURE" semantic actions only.
- var(--vibrant-pink): Delete button fill, validation error text, "DANGER" semantic actions only. Never use for decorative elements.
- var(--safety-orange): ECS consistency warnings and unsaved-changes dirty indicator dot only.

Source: CONTEXT.md D-10, RESEARCH.md Vibrant Decay tokens table, globals.css direct read, AnchorOverlay.module.css pattern.

## Form Field Contract

### Input Types

| Field Type | Element | Styling |
|------------|---------|---------|
| String | `<input type="text">` | Full-width, 14px, white text, black bg, border: 1px solid rgba(255,255,255,0.1), padding: var(--space-xs) var(--space-sm), focus: border-color var(--vibrant-cyan) |
| Number | `<input type="number">` | Same as string, width: 120px |
| Boolean | `<input type="checkbox">` | accent-color: var(--vibrant-cyan); label inline-flex gap var(--space-xs) |
| Enum | `<select>` | Same border/padding as text input; background: #0a0a0a; color: var(--white) |

### Validation Error Display

- Shown below the field on save attempt or on blur if field has been touched.
- Color: `var(--vibrant-pink)`, 12px label size.
- Prefix: `ERROR:` in uppercase before the message (e.g., `ERROR: Required field missing`).
- Icon: no icon — text only for dev tool simplicity.

### Inline ECS Consistency Warnings

- Shown as a warning banner below the component list when ECS rules detect a violation (non-blocking until Save).
- Background: `rgba(255,149,0,0.1)`, border-left: `3px solid var(--safety-orange)`, padding: `var(--space-sm) var(--space-md)`.
- Text: `var(--safety-orange)`, 12px label size, prefix `WARN:`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — save | `SAVE_TEMPLATE` |
| Primary CTA — create new | `NEW_TEMPLATE` |
| Primary CTA — clone | `CLONE_TEMPLATE` |
| Empty state heading (no item selected) | `NO_ITEM_SELECTED` |
| Empty state body (no item selected) | `Select an entry from the sidebar to begin editing.` |
| Empty state heading (section empty) | `SECTION_EMPTY` |
| Empty state body (section empty) | `No files found in this section. Use NEW_TEMPLATE to create the first entry.` |
| Error state — save failed | `SAVE_FAILED: Changes could not be written to disk. Check API route logs.` |
| Error state — load failed | `LOAD_FAILED: Could not read file. The entry may have been deleted or is malformed.` |
| Validation error — required field | `ERROR: "[field_name]" is required by the [ComponentName] schema.` |
| Validation error — wrong type | `ERROR: "[field_name]" must be a [expected_type].` |
| ECS consistency warning | `WARN: [rule message from ECS_RULES entry] — Fix before saving.` |
| Destructive — delete confirmation heading | `CONFIRM_DELETE` |
| Destructive — delete confirmation body | `This will permanently remove "[template_name].json" from disk. This cannot be undone.` |
| Destructive — delete confirm button | `DELETE_FILE` |
| Destructive — delete cancel button | `KEEP_TEMPLATE` |
| Dirty indicator tooltip | `Unsaved changes` |
| Component Schema Viewer — read-only notice | `SCHEMA: Read-only. Edit the TypeScript source to change this definition.` |

Terminology rules (from CONTEXT.md D-09, D-10 and HUB-07 established convention):
- Use `TEMPLATE`, not "Record" or "Item".
- Use `SAVE_TEMPLATE`, not "Save" alone.
- Use `CLONE_TEMPLATE`, not "Duplicate" or "Copy".
- Use `DELETE_FILE`, not "Remove" or "Delete Template".
- Use `KEEP_TEMPLATE` for the cancel/stay action on delete confirmation dialogs (parallel to `KEEP_EDITING` for the unsaved-changes guard).
- Error prefixes: `ERROR:` (blocking validation), `WARN:` (ECS rule, non-blocking), `SAVE_FAILED:`, `LOAD_FAILED:`.
- All heading-level copy is uppercase with underscores to match the Nirmata Vibrant Decay terminal aesthetic (e.g., `NO_ITEM_SELECTED`, `CONFIRM_DELETE`, `SECTION_EMPTY`).

## Interaction Contract

### Keyboard Shortcuts

| Shortcut | Action |
|----------|--------|
| Cmd+S / Ctrl+S | Save current template (only when editor is focused and dirty) |
| Escape | Close delete confirmation dialog |

Note: Cmd+N (new template) is in Claude's discretion per CONTEXT.md. Recommend implementing but not required for MVP.

### Unsaved Changes Guard

- When an editor is dirty (modified since last save), show a 6px amber dot (`var(--safety-orange)`) adjacent to the template name in the sidebar and in the page header.
- If user clicks a different sidebar item while dirty: show an inline confirm banner (`"You have unsaved changes. Save or discard before switching."`) — do not use a browser `confirm()` dialog.
- Discard button copy: `DISCARD_CHANGES` (vibrant-pink text, no fill).
- Stay button copy: `KEEP_EDITING` (vibrant-cyan text, no fill).

### Delete Confirmation Dialog

- Rendered as a centered overlay (`position: fixed; inset: 0; z-index: 300`).
- Background: `var(--overlay-bg)`.
- Modal: `max-width: 480px`, `padding: var(--space-xl)`, black bg, `border: 1px solid rgba(255,255,255,0.1)`.
- Heading: 24px semibold, uppercase, white.
- Body: 14px regular, `rgba(255,255,255,0.7)`.
- Button row: `gap: var(--space-xl)`, `DELETE_FILE` button: `background: var(--vibrant-pink); color: var(--white)`, `KEEP_TEMPLATE` button: transparent with `border: 1px solid rgba(255,255,255,0.3); color: var(--white)`.

### Save Flow

1. User clicks `SAVE_TEMPLATE` or presses Cmd+S.
2. Client runs Zod `safeParse` on current form state. If errors: show inline field errors, abort.
3. If Zod passes: run ECS consistency rules. If blocking violation: show warning banner, abort.
4. If all pass: call `PUT /api/dev/gamedata/[type]/[name]`.
5. On success: clear dirty state, remove amber dot, show ephemeral success indicator (vibrant-cyan left-border flash for 1s on the panel header — CSS transition, no JS timer visible to user).
6. On failure: show `SAVE_FAILED:` error message below Save button.

## Accessibility

- All interactive elements: `focus-visible` outline — `outline: 2px solid var(--white); outline-offset: 2px` (established pattern from AnchorOverlay.module.css).
- `prefers-reduced-motion`: disable all CSS transitions and animations (consistent with styles.module.css `@media (prefers-reduced-motion: reduce)` block).
- Sidebar tree items use `role="treeitem"`, `aria-selected`, `aria-expanded` where appropriate.
- Delete confirmation dialog: `role="dialog"`, `aria-labelledby` pointing to heading, focus trapped while open, returns focus to trigger button on close.
- Form fields: every `<input>` and `<select>` has an associated `<label>` via `htmlFor`.
- This is a developer-only tool — WCAG 2.1 AA is the target, not AAA.
